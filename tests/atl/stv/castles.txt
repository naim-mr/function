Castles -- original model (STV built-in benchmark)
==================================================

Reference
---------
Tool : STV (StraTegic Verifier), W. Jamroga, D. Kurpiewski, et al.
       https://github.com/blackbat13/stv   (newer: blackbat13/stv_v2)
Paper: "Fixpoint Approximation of Strategic Abilities under Imperfect
        Information", AAMAS 2017 / https://arxiv.org/pdf/1612.02684
Also used in: "Approximating Strategic Abilities under Imperfect
        Information: a Naive Approach", https://arxiv.org/pdf/1510.06587

In STV "Castles" and "TianJi" are the two reference classes used to measure
the performance of ATL_ir model checking; they are generated by built-in
model generators (not stored as a single text file), parameterised by the
number of castles / workers.

Informal model
--------------
There are several castles, each defended by a number of workers. Each
worker is an agent that, every round, may:

    attack (a neighbouring castle)  |  defend (its own castle)  |  idle

A castle is "defeated" once all of its workers are dead. An attack by a
worker kills one enemy worker unless that strike is matched by a defending
worker. Workers of the same castle form a coalition.

State = the number of alive workers of each castle (numeric).

Strategic property (the one encoded for FuncTion)
-------------------------------------------------
A coalition of the workers of castle 1 can defeat castle 2:

    << workers_of_castle_1 >>  F  ( castle_2 defeated )

i.e. there is a joint strategy of castle-1 workers driving the enemy
worker count to 0, whatever the other castles do.

C transcription: ../castles.c
  (2 castles; HP = number of alive workers; "attack" lowers enemy HP)

Parameterisation for a benchmark family
---------------------------------------
Vary the initial worker counts (hp1, hp2) and/or the number of castles to
obtain Castles_2, Castles_3, ... of increasing size.
