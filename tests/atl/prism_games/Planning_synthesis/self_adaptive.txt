Collective Adaptive Systems Resilience -- original model (CMU)
=============================================================

Reference
---------
Tool : PRISM-games (turn-based stochastic multi-player games, rPATL).
Paper: T. J. Glazier, J. Camara, B. Schmerl, D. Garlan,
       "Analyzing Resilience Properties of Different Topologies of Collective
        Adaptive Systems" (Carnegie Mellon University).

Informal model (from the paper)
-------------------------------
A collective of N self-adaptive managers (CAS) -- e.g. the multi-region
deployments of a Netflix-like system -- cooperates to defend against an external
attacker. It is a turn-based stochastic game with TWO players: all self-adaptive
managers are modelled as ONE cooperative coalition (CAS), and the attacker (ATT)
is the adversary. Each member can detect an attack (with a probability that
grows with the attacker's deployed resources), defend, and NOTIFY others
according to a communication topology (line, ring, mesh, tree, star, full); a
notified member ADAPTS and becomes invulnerable to the breach. The attacker has
bounded resources it deploys against members. The metric is the percentage of
members compromised; the rPATL query is

    <<ATT>> R{"compromised"}max=? [ F stop ]

i.e. the maximum number the attacker can compromise whatever the CAS does.
KEY FINDING: resilience is topology-dependent -- "line" lets the attacker
compromise ~100%, "full" only ~39% -- so notification/adaptation saves members,
but not all against a strong attacker.

De-probabilised version for FuncTion
------------------------------------
Two-player split (cooperative CAS = coalition, attacker = adversary), with the
attacker's resources de-probabilised as a bounded breach budget and notification
de-probabilised as "a notified member adapts (becomes invulnerable)":

    << cas >>  G  ( compromised < N )     resilience -- expected TRUE

C transcription: ../Planning_synthesis/self_adaptive.c
  (each round the CAS notifies one member -> it adapts; the attacker breaches one
   still-vulnerable member while it has resources; the loop runs until every
   member is settled -- adapted or compromised -- tracked by a `vulnerable`
   counter that starts at N.)

Why TRUE: each round the collective adapts a member before the breach lands, so
at least one member is always saved and the whole collective is never fully
compromised (compromised < N) -- the qualitative core of "the topology provides
resilience". A stronger invariant << cas >> G (compromised <= adapted) also
holds (losses never exceed saves, so at least half stay safe). Dually,
<< att >> F (compromised >= N) -- "the attacker compromises the WHOLE
collective" -- is expected UNKNOWN, since notification adapts members the
attacker can then no longer breach (matching that even the worst topology is
not always 100% compromised, and good topologies keep a majority safe).
