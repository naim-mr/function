IPv4 Zeroconf Address Allocation -- original model (PRISM case study)
===================================================================

Reference
---------
Tool : PRISM (DTMC/MDP/PTA).
       https://www.prismmodelchecker.org/casestudies/zeroconf.php
Model: IPv4 Zeroconf dynamic self-configuration protocol.

Informal model
--------------
A host joining a network without a DHCP server self-assigns a link-local IP
address: it picks a candidate, probes the network, and -- if no other host
defends the address -- configures it. Conflicts and message loss are
stochastic. The original PRISM analysis bounds the probability / expected
time of (mis)configuration.

De-probabilised version for FuncTion
------------------------------------
This is NOT a PRISM-games model: we IMPOSE the game split (the joining host is
the controller -> coalition; the network conflicts -> adversary) and ask sure
configuration:

    << host >>  F  ( address configured )

C transcription: ../Communication_protocols/zeroconf.c
  (the host probes candidate addresses; the network may raise a conflict, but
   only a bounded number of times, so the host configures an address.)
  The conflict bound is NOT fixed: it is chosen adversarially (input("env")),
  so the verdict must hold for any finite number of conflicts -- which subsumes
  the protocol constant RFC 3927 MAX_CONFLICTS = 10 and every larger value.

NOTE: stronger modelling step than the PRISM-games de-prob (single-agent
DTMC/MDP). Models "conflict with prob < 1" by an adversary-chosen FINITE
conflict bound (input("env"), not fixed in advance -- see BOUNDED_ADVERSARY.md) --
unbounded conflicts would block configuration forever, whereas the
probabilistic original configures with prob 1.

Why this modelling corresponds
------------------------------
Schematic abstraction at the game level:
  - controllability split: the host is the coalition; the address conflicts
    are the uncontrolled (bounded) adversary;
  - objective: reachability of "address configured";
  - probabilistic conflicts -> bounded demonic non-determinism. So  << host >>
    F configured  is the qualitative core of  P[ configured ] = 1.
Preserved: host-vs-network structure + the configuration objective.
Abstracted: the exact (mis)configuration probabilities / expected time.
