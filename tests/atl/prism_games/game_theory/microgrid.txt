Microgrid Demand-Side Management -- original model (PRISM-games)
==============================================================

Reference
---------
Tool : PRISM-games (stochastic multi-player games, rPATL).
Case study page: https://www.prismmodelchecker.org/games/casestudies/mdsm.php
Paper: Chen, Forejt, Kwiatkowska, Parker, Simaitis, et al.

Informal model
--------------
A set of households connected to a microgrid each follow a (randomised)
demand-side-management protocol: a household runs a load only if the
current energy price (a function of total load) is below an agreed limit.
The original analysis is a stochastic game with rPATL properties about the
expected cost / fairness when some households deviate.

De-probabilised version for FuncTion
------------------------------------
Model the households as an adversary issuing load demands and a grid
controller (coalition) that admits or defers loads. The strategic
safety property:

    << controller >>  G  ( total_load <= cap )

C transcription: ../game_theory/microgrid.c
  (N households, each round the controller admits a subset so that the
   instantaneous load never exceeds the cap. Both the household count n and the
   capacity cap are arbitrary -- read from input("hh"), not fixed in advance --
   so the verdict must hold for any grid size and any capacity. This also
   avoids a degenerate fixed instance where cap exceeds the maximum possible
   load and the property would hold vacuously.)

NOTE: drops the probabilistic / cost (reward) dimension of the original
rPATL model; keeps the strategic safety core.

Why this modelling corresponds
------------------------------
Schematic abstraction at the game level (not a transcription of the PRISM
source):
  - same controllability split: the grid controller is the coalition; the
    households (their load demands) are the uncontrolled environment;
  - same objective class: a SAFETY invariant on the instantaneous load;
  - the households' randomised demand protocol -> demonic non-determinism
    (any demand pattern). So  << ctrl >> G (load <= cap)  is the qualitative
    core of the rPATL question "can the controller keep the grid within
    limits whatever the households do", i.e. the worst-case (prob-1) reading.
Preserved: controller-vs-demand structure + the load-bound objective.
Abstracted: the expected energy cost / fairness rewards of the rPATL specs.
